# 生成側プロンプト雛形 — レビュー層が載るHTMLを作らせる

AIに自己完結HTMLを生成させるとき、この指示をシステムプロンプト／タスク冒頭に含める。
そのまま貼って使ってよい。`{{...}}` は生成ごとに書き換える変数。

---

## 貼り付け用テンプレート

```
このHTMLには、読み手がブラウザ上で直接コメントを入れられる「レビュー注釈レイヤー」を
載せる。守ることは1つだけ: `</body>` の直前、閉じタグの直前の行に次の1行を入れる。

<script src="{{RV_LAYER_PATH}}"></script>

{{RV_LAYER_PATH}} は "rv-layer.js" への相対パス（例: 生成物と同じディレクトリに
rv-layer.js を置くなら "rv-layer.js"、1階層上に置くなら "../rv-layer.js"）。

レビュー層は既定では画面に出ない。読み手がURL末尾に #rv を付けて開いたときだけ現れる
（詳細は同梱の README.md）。生成するHTML側は何もしなくてよい。script 1行を置くだけでいい。

## やってはいけないこと

- レビュー層の見た目・挙動を真似た独自UIを作らない（コメント風の吹き出し・付箋・
  「レビュー」ボタン等を自前で実装しない。すでにrv-layer.jsが provide する）
- 以下のIDをページ本文の要素に使わない（レビュー層が予約している。衝突すると
  レビュー層は起動を中止し、画面にバナーで警告を出す）:

  rvorphan, rvbar, rvcount, rvdone, rvcopy, rvexport, rvpick, rvclear,
  rvpop, rvquote, rvimgs, rvnote, rvdel, rvcancel, rvsave,
  rvdonepanel, rvdonelist, rvmarks, rvcrop, rvhover, rvtoast

- 本文の要素に `mark.rv` というタグ+クラスの組み合わせ、`.rvnum` というクラス、
  `<body>` に `rvpicking` というクラスを使わない（同じ理由）
- `<script>` タグを `</body>` より後ろに置かない。レビュー層は本文の走査範囲を
  `document.body` として初期化するため、bodyの外側の要素は対象外になる
- 本文中で `window.__rvResolved` という変数名を別の用途に使わない
  （済み消し込みの契約で予約されている。詳細は specs/resolved-contract.md）
- 外部CDN・外部フォント・外部画像への依存を増やさない（rv-layer.js自体が
  外部依存ゼロで動く設計のため、本文側もそれに揃える）
- iframeの中にレビュー対象のコンテンツを置かない（親ページのレビュー層は
  iframe内の選択・クリックを取得できない）
```

## 参考: レビュー層が本文構造について前提にしていること（壊さない方が無難）

生成するHTMLがこれらから外れても致命的には壊れない（多くは「未照合」表示に落ちるだけ）が、
レビューの質を上げたいなら意識するとよい。

- **見出し階層**: `h2`〜`h4` を意味のあるセクション区切りに使うと、コメントに
  「[セクション名]」が正しく付く。見出しが無い/深すぎる/浅すぎると「導入」に丸められる
- **セクションの繰り返し構造**: `.section` や `.wrap` のようなラッパーを複数回繰り返す
  構成でも、選択・クリックは `document.body` 全体が対象なので問題なく動く
- **flex/gridコンテナ内の複数要素にまたがる選択**: 選択範囲がコンテナをまたぐと、
  レビュー層はコンテナ全体を1つの注釈対象として扱う（意図しない広い範囲になりうる）ので、
  1つの主張は1つの要素にまとめる方が注釈しやすい
- **同じ文言・同じ構造のカードが並ぶ場合**: 何番目のカードかを周辺文脈で判別する
  仕組みがあるが、完全に同一のテキスト・同一のマークアップを持つ要素が多いページでは
  改訂後の再照合精度が落ちる可能性がある

## テンプレートを使う場合

`templates/digital-agency.html` は上記を満たした状態で `</body>` 直前に読み込み行が
