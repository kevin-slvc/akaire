# 適用側プロンプト雛形 — zipを受け取って修正し、対応IDを申告する

レビューコメントのzip（`specs/review-package.md` 参照）を受け取ったAIに渡す指示。
そのまま貼って使ってよい。

---

## 貼り付け用テンプレート

```
zipで受け取ったレビューコメントに対応する。手順は以下の通り。

1. zipを展開する。構成は review.md / source/<元のファイル名>.html / images/<画像ファイル>。
   **修正対象は source/ 配下のHTMLそのもの**（review.mdの冒頭「編集対象」行にファイル名が
   書いてある。zipに同梱されているので、別途元HTMLを探しに行く必要はない）
2. review.md を読む。冒頭の「## AIへの対応手順」に済み消し込みの手順が書いてある
   （下記4〜5と同じ内容）。続く「## コメント」以下、各コメントは
   "### <番号>. <コメントID>" の見出しで始まり、種別・セクション・対象・修正指示・添付が
   箇条書きで続く。**番号は表示上の並び順で毎回変わりうる。修正対応の記録には必ず
   見出しの <コメントID> の値を使うこと**（番号ではない）
3. 「対象」（引用テキスト）が指す本文の場所を、source/配下のHTMLの中から特定する。
   「セクション」の見出し名・引用テキスト・（種別が「枠」のコメントなら）タグ名と
   クラスと引用テキストの先頭部分が手がかり
4. 「修正指示」に従って修正する。「添付」に images/ 配下のパスがあるコメントは
   その画像を参照しながら判断する
5. 対応できたコメントのIDだけを集め、source/配下のHTMLの改訂版の </body> 直前
   （rv-layer.js の読み込み行はそのまま残す。前でも後でもよい）に次を追加する:

   <script>window.__rvResolved={rev:"r{今の日時 YYYYMMDDHHMMSS}",ids:["<id1>","<id2>",...]}</script>

   rev は今回限りのユニークな値にする（既存の値を使い回さない）。ids には**対応した
   コメントのIDだけ**を入れる。見たが対応しなかったコメントのIDは入れない
6. source/配下のHTMLに既存の window.__rvResolved が既に埋め込まれている場合（前回の対応分）は、
   **古いタグを消して1つにまとめる**。ids は前回分+今回分の和集合、rev は今回の新しい値にする。

   1つのHTMLに __rvResolved のタグを2つ以上置いてはいけない。これはただの
   グローバル変数への代入なので、後から実行されたタグが前のタグを上書きし、
   **先に書いたタグのidsは一度も処理されない**（レイヤーは変数を1回読むだけで、
   ページ内のタグを探しに行かない）。エラーは出ないので、消し込みが黙って落ちる。

   和集合にすると、読み手が「戻す」で未済みへ戻したコメントも、今回の新しい rev に
   idsとして載っていれば再び済みへ落ちる。戻されたものを未済みのまま残したいなら、
   そのIDを ids から外す
7. 改訂したHTMLをどう返すか（zip化する・元のパスに上書きする・差分だけ示す等）は、
   このプロンプトを使う側の運用に合わせる。この雛形自体はファイルの受け渡し方法を規定しない

## 対応できなかったコメントがある場合

無理に ids へ含めない。対応できなかった理由（情報不足・仕様上不可能・優先度判断で保留、等）
を、コメントのIDと合わせて人間へ報告する文面に残す。ids に入れなければ、そのコメントは
次にページを開いたときも「未済み」のまま表示され続ける。

## 種別ごとの注意

- 種別「枠」のコメント: 文字列の引用ではなく、表・カード・図などブロック単位への指摘。
  タグ名・クラス・引用テキストの先頭部分から該当ブロックを特定する
- 種別「切り取り」のコメント: 画面上で矩形に囲った範囲への指摘。px寸法・囲みを含む要素・
  引用テキストが手がかり。画面のどこを指しているかの厳密な再現は不要で、記載された
  手がかりから該当箇所を推測して対応する
- 「添付」に `images/...` パスがある行は、そのパスの画像ファイルを実際に開いて確認してから
  対応する（ファイル名や有無だけで判断しない）
- 「添付」が `（zip未収録：原寸を取得できず、サムネイルもなし）` の行は画像データが
  存在しない。「修正指示」のテキストだけで対応を判断する

## 修正後にやらないこと

- rv-layer.js の読み込み行を削除しない
- 予約済みのID・クラス（prompts/generate-html.md の「予約している」一覧）を新規要素に使わない
- 対応していないコメントのIDを ids に含めて「済み」を偽装しない
```
