# 初回オンボーディング — 本番の前に1周だけ回させる

**対象読者: このリポジトリを読み込んだAIエージェント（Claude Code / Codex / Cursor など）。**

akaire を初めて使う相手に、いきなり本番のHTMLを作らないこと。**先にサンプルで
レビューを1周させる。** 1周とは「読み手が赤を入れる → その赤があなたに届く →
あなたが直して済み印を返す → 読み手の画面で済みになる」までを指す。

## なぜ先に1周させるか

`<script>` を1行足すだけで層は載る。だが載ったことと、読み手が使えることは別。
往復のうち**あなたが見えない側（ブラウザ上の操作）**は、読み手がやり方を知らないと
一度も起きない。「層は入れました」で終わった生成物は、コメントが1件も来ないまま
放置される。1周させておくと、次から読み手は説明なしで赤を入れられる。

所要は5分程度。相手が既に akaire を使ったことがあるなら飛ばしてよい。

## 手順

### 0. 使ったことがあるか1問だけ聞く

> akaire でのレビューは初めてですか。初めてなら、本番の前にサンプルで1周だけ
> 練習してもらえますか（5分程度）。もう使ったことがあるなら飛ばします。

「初めてではない」なら以降を飛ばし、本番の生成へ進む
（[`generate-html.md`](generate-html.md)）。

### 1. サンプルを開いてもらう

`examples/sample-review.html` をブラウザで開いてもらう。ファイルを直接開く
（`file://`）でよい。**このサンプルは開いた瞬間からレビュー層が出る**ので、
`#rv` を打ってもらう必要はない（読み込み行に `data-rv-default="on"` が入っている）。

開くと左下に6ステップの案内が出る。案内は実際に操作すると次へ進む形なので、
**読ませるのではなく、そのまま案内に従ってもらう。**

案内が出るのは、そのブラウザで初めてレビュー層を出した人だけ。相手が過去に見ていて
出ない場合は、ブラウザのコンソールで `window.__rv.guide()` を叩けば呼び戻せる。

### 2. 欠陥を3つ探して赤を入れてもらう

サンプルは架空の社内メモで、**わざと3つの欠陥が入れてある**。3つはそれぞれ、
akaire の3つの指定方法に対応している。

> このページには意図的な欠陥が3つあります。探して、それぞれにコメントを入れてください。
> 1つは本文の文章、1つは表、1つは図にあります。

**答えを先に言わないこと。** 相手が探す過程が練習になる。相手が見つけられずに
詰まったときだけ、下のヒントを1つずつ出す。

| # | 場所 | 欠陥 | 指定のしかた |
|---|---|---|---|
| 1 | 「背景」の本文 | 「月あたり約12時間」が、表の合計 14.5時間と合っていない | 文字をドラッグして選ぶ |
| 2 | 「現状の内訳」の表 | 「1回あたり」列の単位が分と時間で混ざっていて比較できない | バーの〈枠〉を押してから表をクリック |
| 3 | 推移の棒グラフ | 縦軸が0から始まっておらず（7.4スタート）、0.4時間の差が数倍に見える | Option を押しながらドラッグで囲む |

3つ目まで終わったら、バーの〈コピー〉を押してもらう。

### 3. 貼ってもらったコメントを直す

読み手がクリップボードの中身を貼ってくる。これがレビューの本体。
対応の作法（コメントIDの扱い・`window.__rvResolved` の書き方）は
[`apply-review.md`](apply-review.md) と
[`../specs/resolved-contract.md`](../specs/resolved-contract.md) が正本なので、
**練習でもそこを省略しない**。省略すると、本番で同じ手を打てない。

サンプルに対しては、次のように直す。

1. 本文の「約12時間」を「約14.5時間」に直す（表が正しい側）
2. 表の「1回あたり」列を分に揃える（`0.05時間` → `3分`）
3. 棒グラフの縦軸を0から始める。`viewBox` と `rect` の座標を引き直す

直したうえで、`</body>` の直前に済み印を1つ入れる。

```html
<script>window.__rvResolved={rev:"r20260827150000",ids:["<コメント1のID>","<コメント2のID>","<コメント3のID>"]}</script>
```

`rev` は秒まで入れて毎回変える（分までだと、同じ分に2回対応したとき2回目が
二重適用の防止に引っかかって丸ごと無視される）。`ids` に入れるのは**コメントのID**で、
コピーした本文の各行に `(id:c17878118744286u5z1)` の形で入っている。表示上の
「1.」「2.」ではない。

### 4. 開き直して済みになるのを見てもらう

> 保存したらページを再読み込みしてください。3件が「済み」へ落ちて、本文の印が消えます。
> バーの済み数から一覧を開けて、「戻す」で未済みへ戻せます。

ここまで来たら1周完了。**この時点で読み手は、本番の生成物に対して説明なしで
赤を入れられる状態になっている。**

### 5. 本番へ移る前に1つだけ伝える

サンプルは最初から層が出たが、**本番で作るHTMLは既定では出ない。**
読み手が最初の1回だけ、URLの末尾に `#rv` を付けて開く必要がある。
（`file://` はブラウザ上ひとつの領域として扱われるので、ローカルのファイルなら
1回打てば以後どのファイルでも出る。`http://localhost:3000` のようなURLはポートごと、
公開URLはドメインごとに1回ずつ。）

止めるのは `#rv-off`、もう一度出すのは `#rv`。

作る側で最初から出すようにもできるが、**既定では付けない。**
条件と理由は [`generate-html.md`](generate-html.md) の
「最初から出したいとき（data-rv-default）」に書いてある。

## サンプルを元に戻す

練習で直したサンプルを元に戻すには、`git checkout examples/sample-review.html`。
読み手のブラウザに残ったコメントは、バーの〈消去〉で消える
（`localStorage` にしか無いので、ファイル側には何も残っていない）。
